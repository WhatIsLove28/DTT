# Трекер недельных целей и задач на день (PWA)

Личное приложение для iPhone: устанавливается через Safari → «На экран Домой».
Работает офлайн, данные хранятся только на устройстве. Интерфейс на русском и английском.
Подробный план разработки по фазам — в `PLAN.md`. Работаем строго по одной фазе за раз.

## Стек
- Vite + React 18 + TypeScript (strict)
- vite-plugin-pwa — манифест, service worker, офлайн
- Dexie.js (IndexedDB) — локальная база; dexie-react-hooks для живых запросов
- Zustand — состояние интерфейса (выбранная дата, режим просмотра)
- date-fns + локаль `ru` — вся работа с датами; неделя начинается с понедельника
- Tailwind CSS — стили
- Embla Carousel — горизонтальный свайп между двумя главными экранами
- react-day-picker — выбор даты в календаре
- Vitest — юнит-тесты
- Хостинг: GitHub Pages или Cloudflare Pages (нужен HTTPS для service worker)

## Экраны
1. **Главный** (свайп влево → экран недели):
   - верх — недельные цели: название · цель · факт · иконка статуса;
   - низ — задачи на сегодня, включая просроченные (красная метка).
2. **Неделя** (свайп вправо → главный): 7 столбцов пн–вс, блоки цвета категории,
   высота блока пропорциональна длительности. Справа вверху: переключатель
   «Неделя / День» и кнопка календаря для перехода к любой дате (история).
   Между неделями — стрелки ← →, НЕ свайп (свайп занят переключением экранов).
3. **Настройки** (иконка шестерёнки): категории с цветом, тема оформления
   (системная / светлая / тёмная), язык (авто / русский / English) — обе настройки
   хранятся в localStorage и в бэкап не входят; экспорт/импорт бэкапа.

«+» на экране недели спрашивает, что добавить: задачу или цель. Новая цель может начинаться
с текущей или будущей недели (поле «Начать с недели»; с экрана недели подставляется открытая
неделя): на текущей `startDate` = сегодня, на будущей — её понедельник. До старта такая цель
видна на главном экране в разделе «Запланированные цели».

## Модули
Дополнительные разделы (покупки, расходы, тренировки) живут в `src/modules/<имя>/` и не
смешиваются с целями и задачами. Включаются в настройках (ключ `modules` в meta, входит в бэкап),
на главном экране показываются плитками под «Сегодня», открываются на весь экран через
`uiStore.openModule`. Состав модуля: `types.ts`, `domain.ts` (чистые функции + тесты),
`store.ts` (живое чтение и действия — единственное место, где модуль обращается к Dexie),
экран и плитка; запись в `src/modules/registry.ts`, тексты — в оба словаря.
Таблицы модулей объявляются в `src/db/db.ts` новой версией схемы; всё, чего нет в `CORE_TABLES`,
автоматически попадает в раздел `modules` бэкапа (формат версии 2; версия 1 импортируется).
Валюта и единицы измерения — общие настройки приложения (`src/app/units.ts`, раздел «Единицы»),
а не настройки модулей; хранятся в meta и входят в бэкап. Деньги — целые числа в сотых долях валюты.
Модуль влияет на цели только через `creditGoal` из `src/db/actions.ts` (правило — чистая функция
`taskToCredit` в `src/domain/goalCredit.ts`): напрямую задачи целей модули не меняют.
Быстрое действие плитки открывает модуль с намерением: `openModule(id, 'add')` → проп `intent` экрана.

## Модель данных
```ts
Category   { id, name, color }

Recurrence {                       // общее правило повторения
  type: 'none' | 'daily' | 'every_n_days' | 'weekdays' | 'times_per_week'
  interval?: number                // every_n_days: 2 = «через день»
  weekdays?: number[]              // 1=пн … 7=вс
  timesPerWeek?: number            // гибкий режим: «3 раза в неделю, в любые дни»
}

WeeklyGoal {
  id, title, categoryId,
  schedule: Recurrence             // когда появляются задачи в «Сегодня»
  targetType: 'count' | 'percent', targetValue,
  defaultDurationMin, defaultStartTime?: 'HH:mm',
  repeatWeekly: boolean            // false → цель только на неделю weekStart
  weekStart: date                  // неделя создания
  startDate: date                  // день создания: точка отсчёта every_n_days,
                                   // раньше этой даты задачи не создаются
  endDate?: date                   // выставляется при отключении повтора
  archived?: boolean               // архив: скрыта с главного экрана, история остаётся
}

TaskSeries {                       // шаблон повторяющейся задачи на день
  id, title, categoryId, goalId?, recurrence: Recurrence,
  plannedDurationMin, startTime?: 'HH:mm', startDate, endDate?
}

Task {                             // конкретный экземпляр на дату
  id, title, date, categoryId,
  goalId?, seriesId?,
  source: 'manual' | 'series' | 'goal',
  plannedDurationMin, actualDurationMin?, startTime?: 'HH:mm',
  status: 'todo' | 'in_progress' | 'done' | 'skipped',
  completedAt?,
  deleted?: boolean                // пометка удаления одного экземпляра цели или серии
}
```
Удаление «только эту» у экземпляра цели или серии не стирает запись, а ставит `deleted`
(и `status: 'skipped'`): иначе генерация создала бы экземпляр заново. Такие записи нигде
не показываются и не считаются; доменные функции пропускают их сами. Ручные задачи
удаляются физически.
Уникальность генерации: (goalId, date) и (seriesId, date) — повторный запуск не плодит дубли.
Реализована детерминированным id экземпляра: `g:<goalId>:<date>` и `s:<seriesId>:<date>`.
Id ручных записей — `newId()` из `src/domain/ids.ts` (не `crypto.randomUUID`: он не работает
на айфоне по `http://<IP>`).

## Бизнес-правила (не менять без согласования)
1. **Расписание целей:** поддерживаются оба режима.
   - Фиксированный (`daily`, `every_n_days`, `weekdays`): задача создаётся в конкретные дни.
     `every_n_days` отсчитывается от даты старта, а не от понедельника.
   - Гибкий (`times_per_week`): задача видна в «Сегодня» каждый день, пока недельная
     норма не выполнена. Хранится виртуально и записывается в базу только при выполнении.
     Не больше одного выполнения в день: после отметки задача скрыта до завтра.
   - Недели, когда приложение не открывали, догенерируются при следующем запуске;
     их задачи сразу попадают под правила просрочки (история остаётся честной).
2. **Просрочка:**
   - ручные разовые задачи переносятся в «Сегодня» с красной меткой до выполнения;
   - задачи из недельных целей в конце недели (вс 23:59) получают статус `skipped`;
   - задачи из серий (автоповтор) переносятся до появления следующего экземпляра
     той же серии, после чего старый становится `skipped`.
3. **Засчитывание:** выполнение засчитывается по фактическому дню (`completedAt`),
   прогресс цели считается по неделе, в которую попадает `completedAt`.
   Цель в процентах: выполненные задачи цели за неделю ÷ запланированные на эту неделю
   (для гибкого режима знаменатель — `timesPerWeek`).
4. **Привязка:** ручную задачу или серию можно привязать к цели; выполнение
   увеличивает прогресс этой цели.
5. **Выполнение:** при отметке «Выполнено» спрашивается фактическое время
   (по умолчанию подставлено плановое).
6. **Автоповтор:** любая задача на день и любая недельная цель может повторяться
   (задаётся при создании). Отключение в редакторе выставляет `endDate = сегодня`;
   история сохраняется, будущие экземпляры удаляются.
   Изменение повторяющейся задачи применяется к сегодняшнему и будущим экземплярам.
   Экземпляры, которые новое расписание добавило бы на уже прошедшие дни текущей недели,
   сразу помечаются `deleted` — просрочек задним числом не возникает.
   Архив цели: `archived = true`, `endDate = вчера`, незавершённые экземпляры с сегодняшнего
   дня удаляются. «Эту и последующие» у серии: `endDate` = день перед удаляемой задачей.
7. **Время начала:** необязательно. На экране недели задачи с временем идут
   первыми по порядку времени (время подписано на блоке), затем без времени.
   В режиме «День» задачи с временем стоят на шкале часов, без времени — списком сверху.
   Высота блока = фактическая длительность, если есть, иначе плановая.
   Выполненная задача стоит в день фактического выполнения (`completedAt`), остальные —
   в плановый. Будущие недели показываются как план: экземпляры в базу не пишутся.

## Статусы и цвета
- Задача: серый — не начата · жёлтый — в процессе · зелёный — выполнена ·
  красный — просрочена · зачёркнутый серый — пропущена.
  Тап по иконке: todo → in_progress → done. Свайп по задаче: выполнено / пропустить / удалить.
- Недельная цель: зелёный — норма выполнена · жёлтый — идёт по плану ·
  красный — до конца недели норму уже не набрать
  (оставшихся возможных выполнений меньше, чем нужно).

## Особенности iOS PWA
- `viewport-fit=cover` и отступы `env(safe-area-inset-*)`; `apple-mobile-web-app-capable`.
- `overscroll-behavior: none`, отключить выделение текста и двойной тап-зум на элементах управления.
- При первом запуске вызвать `navigator.storage.persist()`.
- Данные привязаны к домену: после начала использования домен хостинга не менять,
  а если придётся — сначала экспорт JSON.
- Бэкап (экспорт/импорт JSON) обязателен: удаление иконки с экрана «Домой» стирает данные.

## Правила разработки
- Вся логика дат и статусов — чистые функции в `src/domain/`, покрыты тестами Vitest.
  Обязательные граничные случаи: смена месяца и года, цель создана в середине недели,
  отключение повтора, просрочка через границу недели.
- Компоненты не обращаются к Dexie напрямую — только через `src/db/repositories`.
  Изменения данных — через действия в `src/db/actions.ts` (одна транзакция на действие),
  чтение — через живые запросы в `src/db/hooks.ts`.
- Нижние окна (редакторы, подтверждения, календарь) открываются через `uiStore.openSheet`
  и рисуются в `src/sheets/Sheets.tsx`.
- Иконки и splash-экраны создаёт `npm run icons`; теги splash в `index.html` вручную не править.
- Перед написанием кода показывай план и жди подтверждения.
- После каждой фазы: `npm run test`, `npm run build`, без ошибок TypeScript.
- Тексты интерфейса — только через словарь `t` из `src/i18n` (`ru.ts` задаёт тип, `en.ts`
  обязан иметь те же ключи). `t` меняется при смене языка, поэтому читать его нужно внутри
  компонента или функции, а не в константе модуля. Даты — `formatDate` / `formatDateRange`
  из `src/i18n` (шаблоны лежат в словаре). Неделя начинается с понедельника в любом языке.
  Новый язык — ещё один файл словаря и запись в `DICTS` / `LOCALES`.
- Пользовательские данные не переводятся; стартовые категории создаются на языке первого запуска.

## Команды
- `npm run dev -- --host` — dev-сервер, доступный с айфона в той же Wi-Fi сети
- `npm run test` — тесты
- `npm run build && npm run preview` — проверка production-сборки и service worker
- `npm run icons` — перегенерировать иконки и splash-экраны
- Тестовые данные в dev-сборке: адрес с `?seed=1` (заполнить пустую базу) или `?seed=reset`
