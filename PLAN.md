# План разработки (PWA)

Правило: одна фаза — одна сессия Claude Code. В начале сессии — режим планирования
(Shift+Tab), в конце — проверка на айфоне, `git commit`, затем `/clear`.

---

## Фаза 0. Подготовка (вручную)
- [ ] Установить Node.js LTS, Git, Claude Code.
- [ ] Создать пустую папку проекта, положить в неё `CLAUDE.md` и `PLAN.md`, выполнить `git init`.
- [ ] Создать репозиторий на GitHub (понадобится для хостинга на фазе 8).

## Фаза 1. Каркас
- Vite + React + TS + Tailwind + vite-plugin-pwa (манифест, иконки-заглушки, офлайн).
- Два экрана в Embla Carousel со свайпом в обе стороны, индикатор текущего экрана.
- Кнопка настроек, пустой экран настроек.
- Safe-area отступы, тёмная и светлая тема по системной настройке.
- Компоненты: `StatusIcon`, `TaskCard`, `GoalRow`, `BottomSheet` (модальное окно снизу).

**Готово, если:** открывается на айфоне по адресу `http://<IP-компьютера>:5173`,
свайп переключает экраны, вёрстка не залезает под чёлку и полоску «Домой».

## Фаза 2. Данные и доменная логика ⭐ самая важная
- Схема Dexie (версия 1) по модели из `CLAUDE.md`, репозитории.
- Чистые функции в `src/domain/`:
  - `isScheduledOn(recurrence, startDate, date)`
  - `generateForWeek(weekStart)` — экземпляры из целей и серий, идемпотентно
  - `getTodayList(today)` — задачи на сегодня + просроченные + виртуальные гибкие
  - `applyOverdueRules(today)` — переводы в `skipped` по правилам
  - `goalProgress(goal, weekStart)` и `goalStatus(goal, weekStart, today)`
- Тесты Vitest на все функции и граничные случаи из `CLAUDE.md`.
- Тестовые данные (seed) для разработки, включаются флагом.

**Готово, если:** `npm run test` зелёный, сценарии «через день», «пн/ср/пт»,
«3 раза в неделю», «цель на одну неделю без повтора» покрыты тестами.

## Фаза 3. Настройки и категории ✅ код готов
- Список категорий, создание, переименование, удаление (с выбором, куда перенести задачи).
- Выбор цвета из палитры примерно на 12 цветов.

## Фаза 4. Главный экран — недельные цели ✅ код готов
- Форма цели: название, категория, расписание (переключатель режимов), цель
  (раз или %), длительность и время по умолчанию, переключатель «Повторять каждую неделю».
- Строка цели: название · цель · факт (например, «2 / 4» или «50 %») · иконка статуса.
- Тап по цели открывает редактор: изменение, отключение повтора, архив.

**Готово, если:** созданная цель сразу даёт задачи в нужные дни и прогресс считается верно.

## Фаза 5. Главный экран — задачи на сегодня ✅ код готов
- Список: просроченные сверху (красная метка), затем задачи по времени начала, затем без времени.
- Форма задачи: название, категория, плановая длительность, время начала (необязательно),
  привязка к цели (необязательно), автоповтор (тот же выбор режимов, что у целей).
- Тап по иконке статуса: todo → in_progress → done; при done открывается окно
  «Сколько заняло?» с подставленной плановой длительностью.
- Свайп по задаче: выполнено / пропустить / удалить. Для повторяющихся задач при удалении
  спрашивать: «только эту» или «эту и последующие».
- Редактор задачи: изменение полей, отключение автоповтора.

**Готово, если:** выполнение привязанной задачи сразу меняет прогресс и цвет цели наверху.

## Фаза 6. Экран недели ✅ код готов
- 7 столбцов пн–вс, заголовок с датами, текущий день подсвечен.
- Блоки цвета категории, высота пропорциональна длительности (факт или план),
  на блоке — название и время начала, если оно задано; выполненные блоки отмечены.
- Режим «День»: шкала часов, задачи со временем стоят на шкале, без времени — списком сверху.
- Справа вверху: переключатель «Неделя / День» и кнопка календаря (react-day-picker)
  для перехода к любой дате, включая прошлые месяцы.
- Стрелки ← → для переключения недель или дней, кнопка «Сегодня».
- Тап по блоку открывает редактор задачи.

**Готово, если:** открытие недели двухмесячной давности показывает реальную историю.

## Фаза 7. Надёжность и шлифовка ✅ код готов
- Экспорт в JSON (через Share Sheet / скачивание) и импорт с подтверждением.
- Напоминание в настройках: «Последний бэкап: N дней назад».
- `navigator.storage.persist()`, обработка обновления service worker («Доступна новая версия»).
- Пустые состояния, плавные анимации, вибро-отклик там, где iOS его поддерживает.
- Нормальные иконки приложения и splash-экраны для iOS.

## Фаза 8. Публикация и установка
Готово в коде: `.github/workflows/deploy.yml` (тесты, сборка, публикация на GitHub Pages),
сборка на относительных путях. Остальное — вручную:
- [ ] Создать репозиторий на GitHub, добавить remote и запушить.
- [ ] Settings → Pages → Build and deployment → Source: «GitHub Actions».
- GitHub Actions → GitHub Pages (или Cloudflare Pages), HTTPS.
- На айфоне: Safari → адрес → «Поделиться» → «На экран Домой».
- Проверить офлайн-режим: включить авиарежим и открыть приложение.
- ⚠️ После этого домен не менять: данные привязаны к нему.

## Осталось проверить вручную
- [ ] На айфоне: свайпы по задачам, вибро-отклик, safe-area, splash-экран, поля даты и времени.

- [ ] Service worker и офлайн — в обычном Chrome или на айфоне (во встроенном браузере Claude не проверить).
- [ ] Плашка «Доступна новая версия» после второй публикации.
